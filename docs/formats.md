# Data formats

Everything the installer reads or writes besides the Nexus collections themselves. Files that ship with the app live in
`src/Core/Data/` (embedded). Each can be overridden without a rebuild by putting a file of the same name in
`<app folder>/order/`.

## Shipped metadata

### `<id>.priority.json` — structured mod order (MO2 separators)

```json
{
  "Schema": 1,
  "AddonId": "a-storywealth",
  "Note": "...",
  "Separators": [
    { "Name": "Fixes", "Categories": ["Bug Fixes"], "NamePatterns": [], "AlwaysShow": false,
      "Mods": [ { "Md5": "…", "Name": "A Storywealth - Some Mod", "Parent": null } ] }
  ]
}
```

Separators are listed lowest priority first. `Mods` inside a separator are in ascending deploy order (last wins).
`Parent` marks a patch / BodySlide set that must directly follow the mod it needs. `AlwaysShow` keeps an empty separator
(the last one, "Added mods", is for the user's own mods). At install time every before/after rule and every real file
conflict still wins over this file (`PriorityOrder.Apply`). Generated by `OrderTool` (see below).

### `<id>.optional.json` — optional install groups

```json
{ "Schema": 1, "AddonId": "a-storywealth",
  "Groups": [ { "Id": "ss2", "Name": "Sim Settlements 2", "Description": "…", "DefaultOn": true,
                "FromOptionalFlag": false, "Source": "collection 4rfeex r47", "Mods": [ { "Md5": "…", "Name": "…" } ] } ] }
```

A group left unticked at setup skips its downloads, extraction, mod-list entries and plugins. `FromOptionalFlag` means the
group is the collection's own Vortex "optional" mods rather than a listed set.

### `addon-options.json` — curated facts about optional mods

```json
{ "Schema": 1, "Names": { "yilurh": "Thuggyverse" },
  "Entries": [ { "Addon": "wrbrop", "Md5": "…", "Name": "Project Valkyrie",
                 "NeedsAddons": ["yilurh"], "NeedsGroups": [], "Note": "" } ] }
```

The Optional tab greys an option out until every add-on slug in `NeedsAddons` is installed and every group in
`NeedsGroups` was installed with the base list. Match is by `Md5` (preferred) or `Name` (the mod's name in its collection).
The collection author's own per-mod `instructions` text is always shown next to the option. Seeded only from instructions
the collection authors wrote.

## Written into an instance

| File | Purpose |
|---|---|
| `ModOrganizer.ini`, `profiles/A StoryWealth/` | the MO2 instance (`modlist.txt` highest priority first, `plugins.txt`, `loadorder.txt`) |
| `mods/<name>_separator/meta.ini` | MO2 separators (marked `aSW-installer-separator`) |
| `.asw-addons.json` | installed add-ons (id, revision, separator, mod folders, hoisted mods, optional picks) and the base list's installed groups / optional picks |
| `.asw/<id>.collection.json` | copy of each collection list that was installed (the Optional tab works offline from these) |
| `.asw-tools.json` | tools moved to `<instance>/Tools` |
| `install-*.log` | one log per run |
| `Tools/` | standalone tools (FO4Edit, Bethini, …) that MO2 executables point to |

## Environment variables

| Variable | Use |
|---|---|
| `ASW_NEXUS_KEY` | Nexus personal API key; overrides the key saved in Settings |
| `ASW_7Z` | full path to `7z.exe` when it is not in a standard location |
| `ASW_UI_SHOT`, `ASW_UI_SIZE` | development only: render every page to PNG files in that folder and exit (`WxH` sets the window size) |

## OrderTool (maintainers)

```
dotnet run --project src/OrderTool -- <collection.json> <instanceDir> <addonId> <out.priority.json>
dotnet run --project src/OrderTool -- optional <base.json> <filter.json> <instanceDir> <addonId> <out.optional.json>
```

The first generates the structured order for a collection from its rules and the real file conflicts of an installed
instance, and prints an A–Z audit. The second derives an optional group from a Nexus "filter" collection (for example the
Sim Settlements 2 group from collection `4rfeex`).
